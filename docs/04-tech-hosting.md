# 04 — Технологии и хостинг

## Стек: рекомендация

**Чистый HTML + CSS + vanilla JS, без сборки и фреймворков.** Причины:
- Ноль зависимостей = деплой на GitHub Pages за минуты, нечему ломаться
- Объём задачи (одна страница, лайтбокс, скролл-анимация нити) не требует React
- Сайт можно открыть двойным кликом по index.html — удобно проверять

Если в ходе работы станет очевидно, что нужен билд (например, для оптимизации
картинок скриптом) — допустим простой npm-скрипт, но артефакт деплоя всё равно
статические файлы.

## Структура репозитория

```
/
├── index.html
├── css/style.css
├── js/main.js          # нить, лайтбокс, звук, появление элементов
├── content.json        # тексты секций 1,2,4,5 (всё личное — здесь)
├── photos/
│   ├── photos.json     # манифест таймлайна (см. 05-photos.md)
│   ├── full/           # оптимизированные фото ~1200px
│   └── thumb/          # превью ~480px для таймлайна
├── audio/              # stamp.mp3/ogg, paper.mp3/ogg
└── docs/               # эта документация (в деплой не мешает)
```

Все пути — **относительные** (`./photos/...`), потому что GitHub Pages
проекта живёт в подпапке `/<repo>/`.

## Производительность (критично: 20–40 фото на мобильном)

- Таймлайн грузит thumb-версии, полный размер — только в лайтбоксе по тапу
- `loading="lazy"` + `decoding="async"` на всех фото кроме первых двух
- WebP с fallback через `<picture>`; целевой вес thumb ≤ 60 КБ, full ≤ 300 КБ
- `width`/`height` заданы, чтобы не прыгала вёрстка (CLS)
- Шрифты: только нужные начертания, `display=swap`

## Доступность

- Осмысленные `alt` у фото (из поля caption манифеста)
- Контраст текста на бумаге ≥ 4.5:1
- `prefers-reduced-motion` отключает анимации нити, оттисков и появления
- Лайтбокс закрывается по Esc и тапу по фону, фокус-ловушка внутри

## Деплой на GitHub Pages — пошагово

1. Создать **приватность репозитория: public** (Pages на бесплатном тарифе
   работает только с публичными репо — учесть, что фото будут технически
   доступны по прямым ссылкам; если это неприемлемо, альтернативы ниже)
2. Запушить статику в ветку `main`, корень репозитория
3. Settings → Pages → Source: `Deploy from a branch` → `main` / `/ (root)`
4. Через 1–2 минуты сайт доступен на `https://<user>.github.io/<repo>/`
5. Проверить с телефона по реальной ссылке, затем генерировать QR-код
   именно на неё

### Если публичность репозитория смущает

- **Netlify Drop** (drop.netlify.com): перетащить папку в браузер — сайт
  в сети за 30 секунд, репозиторий не нужен вовсе. Рекомендуемый запасной
  вариант.
- **Cloudflare Pages / Vercel**: тоже бесплатно, можно из приватного репо.

В любом случае: URL должен быть коротким и стабильным — QR печатается
на упаковке, менять его после печати нельзя. Финальный URL зафиксировать
до генерации QR.

## QR-код

- Генерировать на финальный URL с `https://`
- Уровень коррекции ошибок M или Q (печать на упаковке)
- Обязательно протестировать скан с распечатки, не только с экрана
